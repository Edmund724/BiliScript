# reader 域入口保留宽类型面与双访问通道

> 状态：有效

reader 懒加载域同时存在两种访问方式：常驻/壳侧经 `reader/lazy-reader.ts` 与 `ui/reader-gate.ts` 动态取得域入口，域内 module 之间继续同步直 import。我们决定保留这两条通道，并让 `ReaderDomain = typeof import("./index.js")` 继续覆盖完整域入口，不改用手写窄类型面。

## 考虑过的方案

- **收窄 ReaderDomain 与 barrel 导出面**：手写窄类型面曾在消费方各自交叉收口时漂移；完整类型面让域入口导出变化直接反映到消费侧。barrel 同时服务现有集成测试，删除零消费导出只有局部清理价值，不构成 deepening。
- **统一为单通道**：常驻/壳侧静态直取会把 reader 懒 chunk 拖入常驻图；域内改经 gate 会把同步调用变成绕自身动态装载 seam 的异步跳转。两条通道由调用方所在加载位置决定，不是待消除的重复实现。
- **字符串分发**：不引入；reader 调用面继续使用具名导出。

## 后果

架构评审不得再提议收窄 `ReaderDomain`、统一这两条访问通道或改用字符串分发。零消费导出只在未来因真实需求修改域入口时顺带清理，不单独列为架构候选。
