# 直播间实时伴看只挂浮窗，不加载文摘面板

> 状态：有效

B 站直播间（`live.bilibili.com/<数字房间号>`）支持实时伴看，但整个页面只挂全屏伴看浮窗与一个开关按钮，不加载文摘面板、阅读壳、字幕、概览与文本对话链路。直播一般全屏观看，侧面板没有用武之地；直播没有 `bvid`/`cid`，字幕、概览、章节、缓存与对话历史的身份前提都不成立。

## 考虑过的方案

- **直播间也挂文摘面板，只留对话 tab**：面板、阅读壳与右栏锚点（ADR-0006）都以视频页为前提；对话 tab 依赖文本模型与字幕上下文，而直播只有 live 模型与音视频流。需要拆掉大半依赖才能跑通，收益只是多一个侧面板。否决。
- **只用工具栏图标启动**：全屏时够不着。播放器内开关按钮为入口。

## 后果

- 会话身份是房间号（`MossLiveRoomContext`），每次进入都是新会话，不持久化；换房间时先结束旧会话。
- 房间标题与主播名各一行写入系统提示，不抓弹幕。
- 直播间不下发页面工具：Gemini 在 setup 里只声明联网搜索；MOSS-LIVE 的工具声明在服务端、客户端无法裁剪，只能靠提示词声明不可用并在 `executeTool` 拒绝执行。
- 入口是独立懒加载 chunk（`live-room`），视频页永不加载；`content.ts` 在 `isLiveRoomPage()` 命中时直接分流并返回。
- manifest 的 content script 与 web_accessible_resources 新增 `https://live.bilibili.com/*`，商店权限需重新审核。
- 直播间没有设置抽屉；未配置实时伴看平台时只弹出连接失败提示，配置入口仍在视频页的文摘面板设置中。
