# 视频页实时伴看由浮窗主承载，面板仅保留状态条、伴看记录与设置同源

> 状态：有效

视频页实时伴看统一由播放器内浮窗（`FullscreenLiveOverlay`）承载全双工语音对话与音频快捷控制，全屏与非全屏共用同一组件；会话生命周期从文摘面板拆出，由 `live/live-companion-session.ts` 独立持有，关闭文摘面板只终止文本对话生成与朗读，不销毁伴看连接与浮窗。同时保留文摘面板侧的轻量协同入口与可观测记录，避免入口孤立与工具结果丢失。

## 已定决策

- **双入口与并发打断**：伴看可由播放器控制栏快捷按钮（`#biliscript-player-live-quick-action`）或对话面板输入栏空态发送键（`chat-tab-composer.ts`）发起；启动伴看时通过 `onBeforeStart` 中止当前在途的面板文本生成流。
- **浮窗主承载与首次展开**：语音转写与回复气泡仅渲染在播放器浮窗内，不写入面板文本对话流。首次从空闲启动或进入失败态时默认展开浮窗（`forceExpand: true`），用户最小化为状态胶囊后保持记忆选择。
- **跨全屏宿主迁移与左右吸附**：浮窗监听 `fullscreenchange` / `webkitfullscreenchange` 与宿主 `resize`，自动迁移到当前全屏容器或 `.bpx-player-container`；通过 `viewport-drag.ts` 支持拖动并在松手时按左右边缘就近吸附，保存 `edge: "left" | "right"` 偏移并在宿主尺寸变化或全屏切换后维持该侧对齐。
- **面板侧状态条与伴看记录**：文摘面板打开时，对话区顶部通过 `chat-live-status.ts` 展示伴看连接状态条（连接中/已连接/重连中/失败）及对应恢复浮窗、重试、设置、结束动作（空闲态隐藏）；伴看触发的文本模型委派调用（`LiveTextToolRecord`）同时展示于状态条下并持久化为面板历史中的独立只读「伴看记录」条目（`chat-lists.ts`），不保存语音转写。
- **音频偏好双端同源**：伴看音量、语速、分享视频声音与语音优先四项既可在浮窗音频弹层即时调节，也在文摘面板设置抽屉「实时伴看」分区提供同源入口并共用 `live/live-audio-settings.ts` 持久化。

## 考虑过的备选

- **彻底剥离面板侧所有伴看联动（仅留播放器入口与浮窗）**：会导致在对话面板内看不到伴看运行状态、无法在关闭浮窗后回看文本模型委派的完整 Markdown 结果，也丢失设置抽屉统一找回路径，已被 UX 走查否决。
- **把语音对话直接写入面板 AI 对话历史**：会让语音闲聊污染文本问答上下文并争用历史会话模型，维持两路记录隔离。

## 后果

- 视频页伴看架构从「非全屏用面板、全屏用浮窗」演进为「浮窗全场景主承载 + 面板轻量协同（入口/状态条/只读文本记录/设置）」，与直播间纯浮窗路线（ADR-0024）共用 `FullscreenLiveOverlay` 与 `live-overlay-binding.ts`。
- `FullscreenLiveOverlay` 必须持续处理 `fullscreenchange` 与 `ResizeObserver` 下的宿主迁移和钳制，不能假设静态右上角坐标。
