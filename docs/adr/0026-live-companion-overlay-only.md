# 视频页实时伴看只用浮窗，面板不再承载伴看

> 状态：有效

视频页的实时伴看原先在全屏时用浮窗、非全屏时用文摘面板，并与面板的 AI 对话共用输入栏、历史和上下文，两者互相占用。现统一为：视频页与直播间（ADR-0024）一样，实时伴看只通过浮窗进行，文摘面板中的伴看 UI 全部删除，面板 AI 对话与伴看可同时使用、互不写入。

## 已定决策

- **入口只在播放器**：开启伴看只由播放器控制栏的伴看快捷按钮发起。面板输入栏不再有开启伴看、中断、伴看切换等控件。
- **伴看内容只在浮窗**：伴看的转写与回复仅显示在浮窗，不进入面板对话历史；面板 AI 对话仅显示文本问答。两者各自独立，不共用历史、上下文和发送键。
- **浮窗默认胶囊**：全屏与非全屏都以胶囊形态出现，点击展开。音量、语音优先、分享视频原声等控件只在浮窗内。
- **位置跟随右上角**：浮窗与胶囊默认贴播放器（或全屏元素）右上角；用户拖动后位置以相对右上角的偏移存放，进出全屏后仍贴右上角，不再监听全屏切换。

## 考虑过的备选

- 非全屏仍用面板：与面板对话争用同一条上下文，体验分裂，是本次要消除的问题。
- 伴看与面板共用一份历史：伴看会话与文本问答争用同一条上下文，冲突会留下。
- 按容器比例保存拖动位置：能保住拖到左侧的意图，但复杂度高；接受进出全屏后仍贴右上角的代价。

## 后果

- 全屏观察器、退全屏回到面板的回调与 `data-biliscript-fullscreen-mode` 属性随之删除，浮窗绑定只剩「总是显示」一种模式。
- 拖到容器左侧的位置，在容器尺寸变化后不再保持在左侧。
- 配置入口仍在文摘面板设置抽屉中。
