# ADR-0025：伪轨视频的双语第二路是译文，走独立的批量翻译链

> 状态：有效

无 CC 字幕的视频只有一条 ASR 伪轨（`id=asr`、`subtitleUrl` 为空），第二路字幕无从配对。本篇记的裁决：**这类视频的双语第二行是同一原文段的 LLM 译文，不是第二条轨**；译文只进副轨槽，双语开关按伪轨身份放开，目标语言与 `id_translate-<lang>` 缓存与播放器「实时字幕翻译」共用。

## 背景

- 伪轨的 `lan` 是 `asr-zh`、`subtitleUrl` 为空，选轨控件与副列的装载链都要求 URL 非空，因此它在既有模型里天然配不出第二路；开关置灰的判据是「可装载真轨 < 2」。
- 播放器一侧已经有一整套「原文 + 译文」：`live/interpret-session-controller.ts` 按播放游标滑窗转写与翻译，把译文写进副轨槽（`translate-<目标语言>`），缓存键 `id_translate-<lang>`，目标语言 `liveInterpretTargetLang`。但阅读面板的副行只受 `bilingualSubtitles` 门控、开关对单轨视频又置灰，于是这份译文在面板里永远显示不出来。
- 阅读面板是全文面：搜索、复制、导出、概览、对话都要整份字幕。滑窗只覆盖当前播放窗口，在阅读面上等于残文本。

## 决定

1. **判据是伪轨身份，不是轨数。** `asrScenario = 存在 id==="asr" 且 subtitleUrl 为空的伪轨 && 可装载真轨 < 2`。有 CC 但只有一条轨的视频仍按「本视频只有一条字幕轨」置灰——它要的是一条真轨，不是译文。

2. **译文不是轨。** 只写副轨槽（`acceptSecondarySubtitle`，`id = translate-<目标语言>`、`url` 空），不进 `clip.subtitles`，不动 `selected*` 三项、`subtitleFetchState` 与无字幕原因。主轨恒为原文：复制、导出、概览与对话上下文都只吃主轨，面板不引入「仅译文」三态（那会把「字幕 = 原文」的纪律拆掉，而浮层的三态是显示模式、不是正文源）。

3. **目标语言与缓存与实时字幕翻译共用。** 偏好读 `liveInterpretTargetLang`（14 种词表，与浮层菜单同一份），缓存键沿用 `id_translate-<lang>`（键形是已落盘缓存的兼容面，不改）。浮层看过的译文，面板直接命中，反之亦然；两处各设一个目标语言等于同一视频按两种语言各翻一遍、各花一份钱。

4. **新原文落盘即作废旧译文。** 译文键不含原文身份，改识别语言或换 ASR 平台后同一目标语言会命中旧原文的译文。故 ASR 收尾（`asr/fallback.ts` 的孤儿清理处）在写入成功后调用 `clearTranslatedSubtitleCache`，清掉该视频全部 `translate-*`；键不动、不迁移。

5. **整片 60 秒分片批量，逐片合入。** 分片口径与浮层同一条时间轴（按 `from` 归窗），调度不同：面板一次补齐全片、串行请求，每片翻完立刻 `acceptSecondarySubtitle` 合入并整份落盘，中断后按缓存覆盖续跑。副轨槽在生成期间保持 `ready`——未翻的行折叠，不把整列打成「译文加载中…」占位（那会吞掉已翻好的分片）。

6. **显式动作才花钱。** 打开开关、点副列的语言行、点按钮才发起翻译；缓存全命中则零请求挂载，不设点击门（零成本的路径不需要授权）。进入视频时若开关为开但需要真翻译，副列照铺语言行并给一枚「开始生成译文」，不静默。

7. **片级容错。** 单片失败重试后跳过、其余照跑：有产出 → 槽保持 `ready`，副列说明行写「译文已生成，部分分片失败」，按钮变「补齐失败的 N 片」；零产出 → 槽落 `error`（副行占位「译文加载失败」，重试入口仍在副列）。重试只补失败片与从未请求过的片，ASR 没产出的空片记为「空」不重试，否则无人声的长段落会无限循环。

8. **关开关 / 换视频即中止在飞翻译。** 已发出的分片不追回、已落盘的分片保留；换视频另由写槽前的视频身份与抓取代次自检兜底，旧视频的译文不会落进新槽。中止与重试是本条链自己的机制，不引入到真轨装载链（ADR-0016 的「零取消」仍成立）。

9. **批量器是独立懒加载目标。** `subtitle/asr-translation.ts` 必须登记进 `scripts/build-content.js` 的 `lazyTargets`：轮 A `splitting:false`，未登记的动态 import 会被内联进常驻图，连带它的 `commit → subtitle/core → bilibili/gateway` 静态边一起进主包，直接命中「主包不得静态引用 chunks/」守卫。

## 后果

- 面板的副列在伪轨视频里列出的是译文目标语言（列首标题「译文」），不是轨；CC 视频的双列不受影响。
- 阅读面的双语从此有两种第二路（真轨 / 译文），但它们共用同一个副轨槽、同一条 `secondary-subtitle-ready` 通知与同一份副行渲染，差别只在目标解析与装载器。
- 译文生成是整片成本：长视频第一次开双语要有分钟级等待与相应 token 账；进度只在副列说明行，不加横幅。
