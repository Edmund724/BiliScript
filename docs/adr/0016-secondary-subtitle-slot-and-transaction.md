# ADR-0016：双语副轨独立成槽，走并列接受事务与独立通知 kind

> 状态：有效

字幕双语（同一视频同时显示主轨 + 副轨两行）落地时，最容易被做歪的是把第二路字幕当成「主轨的另一种状态」：共用一个 body、共用整片装载相位、给接受事务加一个角色参数、复用主轨的通知。本篇记的是反过来的那组裁决：**副轨是一份独立的 body、一个独立的装载态、一个并列的接受事务与一个独立的通知 kind，只在渲染与消费点与主轨会合**。落地提交 `ff8d662`（副轨槽 / 并列事务 / 偏好键面）、`0009f9a`（双行渲染 / 双轨搜索 / 选轨弹层）、`64cd9dd`（复制与导出跟随双语）。

## 背景

- `clip` 一次只装**一份** body（`core/state.ts` 的 `subtitleBody`），装载相位 `subtitleFetchState` 是**整片单相位**：`subtitle/fetcher.ts` 写 `idle` / `loading` / `error`，`subtitle/commit.ts` 的成功接受写 `ready`、无字幕出口写 `empty`——一份相位描述整个视频的字幕面，不区分是哪一条轨。
- `selectedSubtitleId` / `selectedSubtitleUrl` / `selectedSubtitleLang` 三项不只是「当前选了哪条轨」：它们是 `core/context-payload.ts` 的 payload 三元组与**变化签名键**，也是 `ai/segment-cache.ts` 段缓存键的输入。
- 渲染只能经**事务通知**驱动（`subtitle/commit.ts` 发、`reader/lifecycle.ts` 收），调用方不得直调渲染——这条锁在加双语前已经存在。
- 字幕缓存是 **per-track 键**（`biliscript_subtitle_cache_${bvid}_${cid}_${sourceKey}`），所以同一视频多轨正文本就能同时在盘上；双语的额外成本落在 state 槽位与装载链，不在网络。
- `SubtitleTrack` 只有 `{id, lan, lanDoc, subtitleUrl, source}`：`ai_type` 在映射阶段被丢掉，**代码层无法区分原文轨与译文轨**，也就无法自动配对。
- 真实 `lan` 有三种形态：人工上传的 CC 轨是 BCP-47（`zh-CN` / `en-US`），B 站 AI 生成轨是 `ai-` + ISO-639-1 小写码（`ai-en`），本扩展自配平台转写出的 ASR 伪轨是 `asr-zh`（`subtitleUrl` 为空）。

## 决定

1. **副轨是第二个 body：`clip.secondarySubtitle` 一个子对象，带自己的装载态 `idle | loading | ready | error`。**

   不复用 `subtitleBody` / `subtitleFetchState`，也不借道 `selectedSubtitle*` 三项。理由是那个相位与那三项各自都有「整片」的语义：`subtitleFetchState` 写一次 `error`，整个字幕 tab 就变成「字幕加载失败」面，而此刻主轨往往已经就绪并正在显示——副轨失败不得阻塞主轨是用户可见的硬约束，复用一个单相位会把「一条轨失败」升级成「整片失败」。`selectedSubtitle*` 三项会把污染带到 AI 侧：副轨写进去就改了上下文签名与段缓存键，而概览 / 对话那些面只吃主轨。三套空态（还没选过副轨 / 本视频没有目标语言轨 / 主副指向同一条轨被自动清空）**不占新位**，由（目标语言 × 轨列表 × 主轨选择 × 副轨 body）投影推导——单一位投影，沿用 ADR-0005 的形状。

2. **副轨的写入走并列的第三个接受事务 `acceptSecondarySubtitle`，不给 `acceptSubtitle` 加角色参数。**

   `acceptSubtitle` 的序列语义是「这条轨**成为生效字幕**」：写 selected 三项 + body + `ready` + 清无字幕原因与详情 + 拉热评 + 发通知；副轨在其中一步都不该发生。把角色塞进去，函数会退化成两组只在部分步骤重叠的分支，读者再也无法从函数名读出「它写完之后主轨面变成了什么」；而这类「写完顺手多做了一件事」的语义，正是要防的误写来源。写纪律要的是**写面只有一个地方**，不是「只有一个函数」：并列事务放同一文件、同形状（runId 自检先于首写 → 整组写 → 发通知），落点与「不写什么」一眼可见。跨槽**不要求原子性**：两槽独立写入、各自通知，「主轨 `ready` + 副轨 `loading`」正是要显示的那个态，不存在需要消灭的「半个双语态」。副轨的并发也沿用既有形状：每列各持一枚在飞值、只禁自己在飞的那一列，跨视频乱序仍由事务门口的 runId 自检兜住；不引入取消与去重（既有装载链上零取消机制）。

3. **新增第二个通知 kind `secondary-subtitle-ready`（只驱动重渲），不复用 `subtitle-ready`。**

   理由不是洁癖而是**副作用收窄**：`subtitle-ready` 的监听者除了重渲列表，还会重启播放同步、刷新概览与快捷问题、调度对话上下文；而副轨到站与这些面无关（AI 面 / 概览面只吃主轨）。该通知的 payload 也**不带轨道身份**，监听者想自己按轨道过滤都做不到；把身份加进 payload 则等于让所有既有监听者都改一遍，还留下「这些面要处理副轨」的暗示。新 kind 让既有监听者**零改动**地不被触发。由此本仓的「渲染 emit 点」从「`subtitle-ready` 一处」扩边为「**只经事务通知，事务通知有两个 kind**」；「调用方不得直调渲染」不变，重渲仍是同一条幂等投影路径。

4. **副轨的「选中」就是目标本身：乐观写入，失败不回退**（与主轨相反，故意不对称）。

   主轨切换失败要退回**已生效**的那条轨，因为 state 里本来就有一份生效值可退；副轨没有「生效值」这一层——目标语言本身就是 state，网络结果只改变**装载态**（加载中 / 失败 · 重试）。更硬的一条：「本视频没有该语言轨」是锁定过的**合法且持久**状态（副轨留空、不自动换语言、不弹回关闭），失败回退到「没有目标」会和它自相矛盾——界面从此分不清「用户没选」与「选了但失败了」。所以失败只写槽里的装载态与状态行旁白，开关保持开、目标保持写、副列停在失败占位，重试入口唯一在弹层副列。

5. **偏好（`bilingualSubtitles` / `secondarySubtitleLang`）进设置键面，但不加设置页控件。**

   开双语是面板里的即时动作（选轨弹层页脚一个开关），在设置抽屉再放一个控件等于造出第二个入口与第二处会漂移的显示面。键面本身则必须进：落进 `DEFAULT_SETTINGS` 即自动获得 `chrome.storage.sync` 跨设备同步、归一化、写白名单与设置快照，并且要参与「恢复默认偏好」——手动维护的复位表最容易漏掉新键，留下「点了恢复默认、双语还开着」的残留。「进键面不加控件」在本仓是安全动作：保存载荷的断言是**包含**关系，不是与键面相等。连带的一条纪律：两键要有跨上下文订阅（现按 `{ sync: [...] }` 形状由选轨弹层叶子自持一份，不在 reader 那份手维护的 watch 清单里），否则会出现「另一个标签页或另一台设备把双语开了、这边开关还停旧态」——「控件与 state 两说」是本仓反复消灭的一族缺陷。

6. **派生内容（Markdown / SRT / TXT）的失效口径：指纹认副轨 body 的引用。**

   早期口径是「指纹表不加副轨输入，副轨变化靠消费点显式失效」。它落不了地：显式失效要在事务、弹层、生命周期三处手动调用，任何新增写入点漏调即静默出旧文本。查证后又发现「开关切换」本来就经 `state.settings` 的引用自动失效（settings 是指纹输入之一），所以原口径下真正剩下的洞只有**一个**：「开关打开后、副轨 body 到站前已经发生过一次消费（复制 / 导出）」⇒ 派生缓存命中 ⇒ 副轨就绪了仍永久出单轨。认引用正好堵这一个洞，且与指纹表既有的四件输入（body / settings / chapters / hotComments 都是引用比对）**同型**，比在三处手动失效更少漏调面。口径边界不变：认的是**引用**不是内容，双语导出仍由消费点在拼装时取两份 body 得出；导出与复制的渲染层拿到的是一枚可选纯解析器，双语关时为 `undefined` ⇒ 单轨路径一次函数调用都不多、输出与加双语前逐字节相同。

7. **语言匹配两级：完整 `lan` 精确命中优先，主语言子标签兜底；只考虑 `subtitleUrl` 非空的真轨。**

   偏好里存的是轨自己的 `lan`（默认 `en-US`），而真实轨的 `lan` 是上面三种形态——纯完整串比对在真实样本上直接匹配失败（`en-US` 对不上 `ai-en`）；反过来只按主语言比对，「同时有人工 `en-US` 轨与 `ai-en` 轨」的混源视频又会**依赖轨序**决定选中谁。两级口径同时要两个性质：完整命中优先（混源视频结果不依赖轨序）→ 主语言兜底（跨形态可比）。匹配收在一个共享叶子里，自动装载与副列投影**同一实现**——两处各写一份会在混源视频上漂移出「装载了一条、副列选中另一条」。ASR 伪轨被排除在副列之外：它是主轨的兜底，不是可对照的第二语言，选它的结果不是「URL 为空」就是「两行同一份文本」，两头都无意义，从入口消除。这是主副两列**唯一**的不对称。

8. **配对是纯函数投影：副行 = 与主轨段时间重叠（严格 > 0）的副轨段的拼接；行的集合恒等于主轨段集合，对齐结果不落 state。**

   两轨的分段边界实测**不完全一致**（合并方向：一段译文可覆盖相邻两主段；无时间偏移），所以按时间重叠匹配即可，不需要容差窗口——加容差反而会把零重叠的相邻段粘上。行的集合必须跟着**主轨**：列表的 `data-index`、搜索、播放高亮、分批渲染全以主轨索引为键，集合若随副轨变（交错插入，或只显示两轨都齐的子集）就要把这四面一起重写，而且副轨缺失会让整行消失、直接违反「主轨永不被副轨阻塞」。对齐结果不落 state：落 state 就要再维护一份失效指纹，而「多一个输入多一个漏点」正是决定 6 的教训——纯函数按副轨 body 的引用缓存区间索引，每行一次二分。配对口径的唯一一份实现被 `tests/subtitle/alignment.test.ts` 钉着，渲染 / 搜索 / 导出三面都走它，不得另写一份。

## 被否决的备选

- **复用 `subtitleFetchState` + 一份 body**：省一个槽，代价是把整片相位与一条轨的装载绑死（决定 1）。
- **给 `acceptSubtitle` 加 role 参数**：省一个函数，代价是主轨事务「成为生效字幕」的语义被稀释成条件分支（决定 2）。
- **复用 `subtitle-ready`，或给它加轨道身份**：省一个 kind，代价是副轨到站带出概览 / 对话副作用，或让既有监听者全部要改（决定 3）。
- **副轨失败回退到空目标**（与主轨一致）：看着对称，代价是「没有该语言轨」这个合法持久态与失败态在界面上不可区分（决定 4）。
- **把双语开关放进设置抽屉**：省掉弹层页脚，代价是两个入口、两处显示面（决定 5）。
- **副轨变化靠显式失效原语**（导出 `invalidateDerivedContent()` 让三处手调）：省掉一项指纹输入，代价是漏调即静默错（决定 6）。
- **副列列出全部轨（含 ASR 伪轨）**、或**按索引硬 zip 两轨**：前者两个方向都无意义，后者在两轨分段边界不一致时整段错配——行的集合必须恒等于主轨段集合（`data-index` / 搜索 / 高亮 / 分批渲染全以主轨索引为键）（决定 7、决定 8）。

## 后果（必须一并接受的代价）

- 状态袋多一个子对象与四个**成组意图**写入原语（loading / ready / error / 清空），写面仍收口，不新增逐字段 setter。
- 通知 kind 从一个变两个：新增通知消费方时必须先问「它要不要概览 / 对话那串副作用」，别默认挂 `subtitle-ready`。
- 副轨装载中 / 失败时，列表副行出占位文案，**占位不可点**；重试入口唯一在弹层副列。「入口唯一」意味着列表里的占位是文本不是控件。
- **列表第二行嵌在 `.biliscript-reading-text` 内**（CSS 网格与时间列零改，行高按可变处理，副行允许折行不截断）。既有消费面因此要修正：解释卡的「选中所在整句」读的就是这个节点的文本，双语态下会把副行译文拼进句子（已在 `reader/explain-pop-ui.ts` 改为剔除副行节点后取文）。凡是把「该节点文本 = 主轨这一句」当前提的代码，双语态下都要重审一遍。
- 双语关 / 副轨槽 `idle` / 该行与副轨零重叠时，副行节点**整个不发射**（不发空 span）；双语关时条目 HTML 与搜索命中集合与单轨态逐字节相同（模板对拍锁）。搜索匹配的是**看得见的两行文本**，占位文案不参与匹配。
- 派生内容多认一项引用输入：任何整体替换副轨 body 的写点都会让派生缓存失效一次——这正是要的；代价是「替换副轨 body 引用」成为一个需要顺手关心派生失效的动作，别在既有写点之外另行替换引用。
- 设置键面多两个键，且必须落进归一化的两张名单之一（否则键面一致性测试红）；两键参与「恢复默认偏好」。
- 缓存面零改动：副轨复用 per-track 键，淘汰 / LRU / TTL 布局不动（缓存族按 `bvid` 计数 ⇒ 同一视频多一份 body 不占保留位、不触发淘汰、与主轨同生共死）；ASR 孤儿清理按伪轨前缀匹配，吃不掉非 ASR 副轨。
- 单轨视频（含只有 ASR 转写轨的视频）的开关是**禁用**态并给一行说明；ASR 不生成译文轨（那是第二条 AI 账单链路，明确不做）。
- 「本视频没有该语言轨」与「副轨装载失败」在列表上都表现为没有副行，区分它们的只有弹层副列的空态文案与状态行旁白——这是入口唯一的代价。

## 重开条件

- **副轨参与 AI 面**（概览 / 对话开始吃副轨）：本条的「两个 kind」是按**副作用集**划分的，不是按轨道数划分；加了副作用就要重开通知的边界，而不是往现有 kind 上叠。
- **三列以上**（主 + 两条副轨）：槽形与投影（决定 1 的单一位投影）要重开。官方播放器也只有两列，诉求未到。
- **派生内容失效机制再改**：若指纹表还要继续膨胀，值得重开的是「消费点显式声明依赖」这类机制，而不是再加一项输入。
